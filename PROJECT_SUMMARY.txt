PROJECT 2 — COLLABORATIVE WORKFLOW MANAGEMENT SYSTEM
================================================================================

IDEA
----
A Jira-like task management platform where teams manage work in real time.
Workspaces contain task boards with Kanban-style columns.

STACK
-----
- Backend: Spring Boot (Java), PostgreSQL, JWT Auth, WebSockets
- Frontend: React + Vite
- Port: Backend 8082, Frontend 3002

WHAT WAS BUILT
--------------
- Two-level RBAC:
  * System level: SYSTEM_ADMIN (can create workspaces) vs SYSTEM_MEMBER
  * Workspace level: ADMIN (can invite/remove/delete) vs MEMBER (can create/move tasks)
- JWT includes roles so frontend reads them without extra API calls
- Workspace creation restricted to SYSTEM_ADMINs
- Members only see workspaces they belong to
- Invite uses dropdown of org users (not free text)
- Assignee uses dropdown of workspace members
- Task state machine: TODO → IN_PROGRESS → REVIEW → DONE
- WebSocket broadcasts on task status changes
- Remove member works with @Modifying @Transactional
- Logged-in user shown at top of every page with role badge
- 18 integration tests (H2 in-memory DB) — all passing
- 14 unit tests — all passing

STATUS: COMPLETE ✅

WHAT STILL NEEDS DOING
-----------------------
- Dockerfile
- GitHub Actions CI/CD pipeline
- AWS deployment (ECS + RDS + ECR + S3)
- File attachments (S3)
- Activity feed per task

PROJECT 4 — CODEBASE Q&A ASSISTANT
================================================================================

IDEA
----
Point it at any project folder. It scans all code files, chunks them
intelligently by function/class boundaries, embeds them using a local
embedding model, stores them in a vector store, and lets you ask questions
about the codebase in plain English. Like Amazon Q but built from scratch.

STACK
-----
- Python 3.12
- FastAPI — REST API
- FAISS — local vector store (cosine similarity search)
- LangChain — orchestration
- Ollama — runs models locally (no API key needed, free)
  * llama3.2 — LLM for answering questions
  * nomic-embed-text — embedding model
- pytest — TDD

HOW IT WORKS
------------
1. POST /index with a folder path
   - Scans all .java, .py, .js, .ts etc files recursively
   - Ignores node_modules, target, .git, __pycache__ etc
   - Chunks code by function/class boundaries (not arbitrary line count)
   - Each chunk stores: file path, function name, start/end line, language, content
   - Embeds each chunk using nomic-embed-text via Ollama
   - Stores vectors + metadata in FAISS

2. POST /query with a question
   - Embeds the question
   - Finds top K most semantically similar chunks via cosine similarity
   - Sends chunks as context to llama3.2
   - LLM answers using ONLY retrieved context (no hallucination)
   - Returns answer + source files/functions/line numbers

3. GET /status — how many chunks indexed, which files
4. DELETE /index — clear everything

WHAT WAS BUILT
--------------
- FileScanner — recursive folder scan with ignore rules
- CodeChunker — splits by function/class boundaries with context detection
- VectorStore — FAISS-based with Ollama embeddings, cosine similarity search
- QAService — retrieval + LLM answering with grounded context
- Indexer — orchestrates scan → chunk → embed → store
- FastAPI routes — /index, /query, /status, DELETE /index
- 39 tests written — 37 passing, 2 failing (minor test assertion issue)

STATUS: IN PROGRESS 🔄
